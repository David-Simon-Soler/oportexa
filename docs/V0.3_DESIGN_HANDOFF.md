# V0.3 Design Handoff

Este documento prepara la fase visual posterior. No es un diseño y no fija paleta, tipografía ni composición final.

## Qué existe

- Next.js server-rendered.
- DAL server-only sobre CORE.
- SearchForm, SiteHeader, GrantCard y Pagination.
- Catálogo, ficha, regiones y nuevas estructuras funcionales de sectores, organismos y beneficiarios.
- Contratos tipados para convocatorias, taxonomías, fondos, provenance y homepage.

## Datos disponibles

Convocatoria: BDNS, título nullable, tipo, presupuesto, estado BDNS, fechas, organismo(s), regiones, sectores, beneficiarios, descripción, finalidad, bases, URLs oficiales, funds y observaciones locales.

Taxonomías: key estable, code/source key, label, slug, total y open count.

## Rutas

`/`, `/subvenciones`, ficha, índices y detalles de regiones, sectores, organismos y beneficiarios. No hay combinaciones arbitrarias ni fondos.

## Jerarquía informativa

En cards: título/estado/BDNS primero; taxonomías y presupuesto después; fechas y procedencia como contexto. En ficha: título y estado, resumen, presupuesto, relaciones, finalidad/descripción, fechas, bases, fondos, provenance y fuente oficial.

## Estados

Loading sólo donde el server rendering lo justifique. Deben existir estados para no resultados, filtro inválido, error de base, entidad 404, dataset parcial y valores desconocidos. Nunca ocultar NULL como cero, false o cerrado.

## Qué no puede cambiar

- CORE-only desde web.
- Server-side y SQL parametrizado.
- Semántica literal de `is_open`.
- Distinción entre fuente BDNS y observaciones locales.
- Arrays N:M.
- URLs canónicas y noindex para búsquedas/filtros.
- Ausencia de auth, pagos, IA y features de usuario.
- No afirmar cobertura nacional completa.
