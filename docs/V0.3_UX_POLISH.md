# V0.3 UX Polish

## Propósito

Este documento registra el pulido UX realizado sobre la implementación visual de V0.3. El objetivo es que una persona pueda entender qué ofrece Oportexa, orientarse por el catálogo, interpretar los estados y verificar cada oportunidad en su fuente oficial.

No añade producto, usuarios, autenticación, alertas, automatización ni nuevas capacidades de datos.

## Orientación y microcopy

- La homepage explica tres acciones: buscar, explorar y verificar.
- El buscador comunica que admite actividad, sector, territorio, organismo y palabras clave.
- Los resultados se expresan como convocatorias encontradas “en los datos disponibles”, evitando sugerir cobertura completa.
- La cobertura parcial se explica con lenguaje humano: las cifras son las convocatorias incorporadas hasta ahora desde BDNS.
- Los errores son accionables y no revelan detalles internos del servidor.

## Búsqueda y filtros

- Los filtros mantienen etiquetas humanas y controles nativos accesibles.
- Cada filtro activo puede retirarse individualmente; también existe “Limpiar filtros”.
- El filtro “Sólo abiertas” indica que su estado procede directamente de BDNS.
- No se infiere una fecha de cierre cuando BDNS no la indica.

## Confianza y procedencia

La primera explicación desarrolla BDNS como Base de Datos Nacional de Subvenciones (BDNS/SNPSAP). Las fichas mantienen el acceso a la publicación oficial y aclaran que Oportexa organiza información pública, no sustituye a la administración ni constituye asesoramiento.

## Estados y datos incompletos

Se mantienen estados explícitos para resultados vacíos, errores, presupuestos desconocidos, fechas no indicadas y ausencia de relaciones. La interfaz no rellena valores oficiales ausentes ni presenta inferencias como hechos.

## Accesibilidad y responsive

- Se añade un enlace “Saltar al contenido” visible al recibir foco.
- Se conservan un H1 por página, labels de formulario, navegación semántica y foco visible.
- Se oscurece el token de texto sutil para mejorar contraste sin cambiar la identidad visual.
- Los controles y mensajes mantienen lectura usable en 320, 390, 768, 1024 y 1440 px mediante el layout responsive existente.

## Decisiones de alcance

- No se rediseñan paleta, tipografía, composición editorial ni componentes aprobados.
- No se añaden combinaciones SEO, related content, mapas, dashboards ni interacción de usuario persistente.
- No se modifica PostgreSQL, CORE, RAW, DAL ni el pipeline.
