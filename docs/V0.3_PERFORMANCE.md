# V0.3 SQL performance baseline

Medición read-only sobre PostgreSQL 16.15 local, dataset de 6.273 convocatorias. Los tiempos son una observación de desarrollo, no un SLO.

| Query | Planning | Execution | Plan dominante |
|---|---:|---:|---|
| recent | 0,505 ms | 5,531 ms | Seq Scan + Sort |
| q | 1,580 ms | 21,139 ms | Seq Scan + Sort |
| region | 3,229 ms | 0,140 ms | joins + Index Scan |
| sector | 2,826 ms | 1,538 ms | joins + Index Scan |
| beneficiary | 2,153 ms | 0,343 ms | joins + Index Scan |
| open | 0,237 ms | 0,360 ms | Index Scan + Sort |
| minBudget | 0,413 ms | 6,060 ms | Seq Scan + Sort |
| region + sector | 1,560 ms | 0,118 ms | joins + Index Only Scan |
| q + region | 1,319 ms | 0,155 ms | joins + Seq Scan |
| taxonomy counts | 0,786 ms | 10,166 ms | Hash Join + Aggregate |
| organization page | 1,868 ms | 0,764 ms | joins + Index Scan |

La búsqueda textual es la consulta más costosa, pero permanece alrededor de 21 ms en este dataset. No se implementa FTS ni se añaden índices especulativos.

La consulta de listado utiliza agregaciones JSON por convocatoria para evitar N+1; las páginas taxonómicas hacen una consulta de identidad/contadores y otra paginada de resultados.
