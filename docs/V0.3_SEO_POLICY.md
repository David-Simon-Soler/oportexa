# V0.3 SEO policy

Fuente de verdad SEO para Product Discovery. Esta política define elegibilidad; no convierte automáticamente toda taxonomía o resultado en una URL indexable.

## Indexable

- Convocatoria individual válida.
- Región válida con inventario real.
- Sector válido con inventario real.
- Organismo válido con identidad estable.
- Beneficiario válido con taxonomía CORE estable.

## Conditional indexable

Una taxonomía sólo puede indexarse cuando tiene inventario suficiente, contenido útil y diferencial, canonical estable, freshness razonable y no presenta duplicación semántica grave. No se fija todavía un threshold numérico definitivo.

## Noindex

- búsquedas internas;
- `q`;
- filtros arbitrarios;
- `sort`;
- `minBudget`;
- `status`;
- combinaciones de filtros;
- taxonomías sin inventario suficiente;
- páginas temporales;
- páginas sin contenido diferencial.

## Canonical

Las taxonomías usan URLs limpias sin query params. Las URLs de fichas conservan el código BDNS y slug de título; un slug incorrecto para un código válido redirige al slug canónico. Las búsquedas y filtros no compiten con las páginas canónicas.

## Sitemap

El sitemap actual mantiene fichas y regiones con inventario. Sectores, organismos y beneficiarios se incorporarán sólo tras pasar la política de utilidad y freshness; no se publican automáticamente todas las taxonomías por existir en CORE.

Con más de 50.000 URLs se deberá particionar por tipo —grants, regions, sectors, organizations, beneficiaries— y crear un sitemap index. No se implementa todavía porque el inventario actual es pequeño.

## Robots y metadata

`robots.ts` permite crawling general y anuncia el sitemap. No se usa `robots.txt` como sustituto de `noindex`: las páginas que necesiten una directiva deberán poder ser rastreadas para verla.

Patrones de metadata:

- `{title} | Oportexa`;
- `Subvenciones en {region} | Oportexa`;
- `Subvenciones de {sector} | Oportexa`;
- `Ayudas y subvenciones de {organization} | Oportexa`;
- `Subvenciones para {beneficiary} | Oportexa`.

No se generará copy con IA ni keyword stuffing.

## Structured data

No se añade un schema dudoso para subvenciones. `BreadcrumbList` es candidato razonable para una fase posterior. `WebSite`/`SearchAction` se evaluará cuando el buscador público tenga su contrato final.
